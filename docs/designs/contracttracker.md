## Problem Statement

People who hold leases, vendor agreements and service agreements miss notice
deadlines and auto-renewals because the dates are buried in clauses. ContractTracker
reads text PDFs, extracts 10 obligation fields with a supporting quote each,
computes the key dates in code, emails reminders before deadlines, and answers
questions across all contracts with [contract, clause] citations, refusing with
"Not found in these contracts" when the answer is absent.

## What Makes This Cool

Every answer and every date can be traced back to a quote in a numbered clause,
and the system says "not found" instead of guessing. The dates are computed by
code, not invented by the model.

## Constraints

- Python 3.11+, Bearing stack python-api, 4 days, one developer.
- OpenRouter only, Haiku-class model, hard budget USD 10, key in `.env`.
- Postgres 16 + pgvector and MailHog in Docker Compose.
- Embeddings: BAAI/bge-small-en-v1.5 on CPU (384 dimensions).
- Text PDFs only via pypdf; 15 to 20 synthetic contracts, no real data.
- 10 fields, each `{value, quote}`; LLM never computes dates; python-dateutil does.
- Unparseable values and ungrounded quotes go to a `needs_review` queue.
- Hybrid search (pgvector + Postgres full-text), cited answers, refusal string.
- Evals under `make check`: extraction accuracy per field, quote grounding,
  recall@5, answer accuracy, refusal accuracy.
- Out of scope: OCR, login, real email, multi-turn chat.

## Premises (accepted in D1)

1. Synthetic contracts are generated from code templates with randomised values,
   and each PDF is written together with a `truth.json` answer key. fpdf2 writes
   the PDFs; pypdf reads them back, so ingestion is tested on real PDF output.
2. Every LLM reply is cached on disk, keyed by hash(prompt version, model, input).
   `make check` replays the cache: offline, free, repeatable. `make eval-live`
   refreshes the cache against OpenRouter and is the only target that spends money.
3. Templates use numbered clause headings (`7.2 Termination`) so the splitter is
   deterministic. The quote check normalises whitespace, line breaks and
   hyphenation on both sides before an exact substring match against the cited clause.
4. Refusal has two layers: a retrieval-score floor in code (refuse without an LLM
   call) and an instruction in the prompt. About a third of the Q&A eval set is
   unanswerable on purpose.

## Approaches Considered

### Approach A: One extraction call per contract (chosen)
The whole contract goes in with numbered clauses; the model returns all 10 fields
as `{value, quote, clause_id}`. Code checks each quote against that clause only.
About 20 calls in total. Effort M, risk low.

### Approach B: Retrieve then extract per field
Rejected for now: about 200 calls and makes extraction depend on TASK-004 search.
Kept as the upgrade path if the per-field eval shows weak fields.

### Approach C: Rules first, LLM fills gaps
Rejected: overfits to our own templates, so evals overstate quality.

## Recommended Approach

Approach A. It fits 4 days and USD 10, `clause_id` makes the quote check exact
and gives the citation for free, and Approach B remains a measured upgrade.

## Success Criteria

- `make check` passes offline with all five eval metrics printed against thresholds.
- Every extracted field either has a grounded quote or sits in `needs_review`.
- Every Q&A answer cites at least one [contract, clause]; unanswerable questions
  return exactly "Not found in these contracts".
- A reminder email for a computed notice deadline appears in MailHog.
- Total OpenRouter spend stays under USD 10, reported by the gateway.
